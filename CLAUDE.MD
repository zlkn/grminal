# Архитектурный проект: GPU-ускоренный эмулятор терминала на чистом Go

Документ описывает архитектуру, технологический стек и план разработки современного, быстрого и расширяемого эмулятора терминала для Linux без технического долга и Cgo-зависимостей.

---

## 1. Технологический стек (Pure Go)

* **Язык разработки:** Go 1.20+ (`CGO_ENABLED=0`).
* **Графическое ядро:** `github.com/hajimehoshi/ebiten/v2` (Vulkan/OpenGL, автоматический батчинг Draw Calls).
* **Рендеринг текста и лигатур:** `github.com/hajimehoshi/ebiten/v2/text/v2` (встроенный шейпер текста на базе HarfBuzz).
* **Шрифт (по умолчанию):** **JetBrains Mono Nerd Font (вариант Mono)** — обязательный шрифт терминала. Файл `fonts/JetBrainsMonoNerdFontMono-Regular.ttf` встраивается в бинарник через `go:embed` (пакет `fonts`), поэтому рантайм-зависимости от файла нет. Моноширинный, с программными лигатурами (OpenType `calt`: `!=`, `->`, `=>`) и полным набором иконок Nerd Font (иконки в варианте Mono ужаты до одной ячейки, чтобы сетка терминала оставалась равномерной). Требования зафиксированы тестами в пакете `fonts` (парсинг, покрытие ASCII, моноширинность, наличие иконок) и `internal/render` (лигатуры).
* **Связь с ОС (Псевдотерминал):** `github.com/creack/pty`.
* **Парсер ANSI/VTE:** кастомный zero-allocation парсер-автомат (`internal/vte/parser.go`, без внешних зависимостей). Поддерживаемые последовательности — см. раздел 7.

---

## 2. Иерархия владения (Слоистая архитектура)

Приложение строится по принципу низкой связности. Графика не знает про системные вызовы, парсер не знает про GPU.

1. **AppState (Вкладки):** Глобальный менеджер, обрабатывающий Hotkeys и переключающий активные вкладки.
2. **LayoutManager (Сплиты):** Менеджер геометрии для текущей вкладки. Распределяет экранное пространство между панелями по структуре «Колонки -> Строки».
3. **Pane (Панель):** Конкретный инстанс терминала с фокусом ввода.
4. **VTE State Machine:** Парсер потока байт из PTY, обновляющий виртуальную сетку символов (Grid).
5. **Scrollback Buffer:** История строк терминала.
6. **Ebitengine Renderer:** Изолированная функция, рисующая Grid в текстуру видеокарты. Отрисовка — по требованию (demand-driven): тяжёлый рендер кадра выполняется только при изменении (вывод PTY, ввод, ресайз), результат кэшируется в offscreen-буфере, который блиттится на экран каждый кадр (двойная буферизация, см. раздел 3).

## 3. Ключевые инженерные решения (Борьба с техдолгом)

* **Отрисовка текста (Лигатуры и Цвета):** Использование блочного рендеринга (Text Runs/Tokenization). Строка бьется на блоки одинакового цвета и стиля, каждый блок рендерится как единое целое. Это сохраняет поддержку лигатур (например, `!=`, `->`) через OpenType `calt`.
* **Управление памятью (Скроллбэк):** Строгий кольцевой буфер (`Ring Buffer`) с предвыделенной памятью (Pre-allocation). При скроллинге или добавлении строк двигаются только указатели `head`/`tail`, аллокации строк не происходят. Использование `sync.Pool` для буферов ввода-вывода.
* **Оконный менеджер (Сплиты):** Отказ от сложных BSP-деревьев в пользу плоской модели Flexbox (Колонки/Строки). Ресайз окон ограничивается через `screen.SubImage(bounds)`, аппаратно отсекая лишнее на GPU.
* **Поддержка Kitty Graphics Protocol:** Добавление реестра текстур `map[uint32]*ebiten.Image`. Изображения хранят координату логической строки терминала (GridY) и сдвигаются/удаляются вместе со скроллбэком, избегая утечек VRAM.
* **Отрисовка по требованию + двойная буферизация (Demand-driven rendering):** вместо безусловного тяжёлого рендера каждый кадр терминал рисуется в персистентный offscreen-буфер (`game.frame`, `ebiten.NewImage`) только когда изменился, а на экран этот буфер блиттится каждый кадр (`screen.DrawImage`). Флаг `dirty` (`atomic.Bool` в `game`) выставляется источниками изменений (вывод PTY через хук `Pane.SetChangeHook`, ввод, ресайз, реконсиляция вкладок) и атомарно сбрасывается при перерисовке буфера (`Swap(false)`). **Важно:** пропускать сам блит нельзя — финальная презентация Ebiten многобуферная, и пропуск записи в экран показывает устаревший бэк-буфер (призраки/дублирование строк, особенно в neovim с дифференциальными обновлениями). Поэтому блит выполняется всегда, а `dirty` гейтит только дорогой рендер (токенизация runs, шейпинг, растеризация глифов). Используется `SetScreenClearedEveryFrame(false)` (не устаревший `FPSMode`/`ScheduleFrame`), поэтому пакет `pane` не зависит от ebiten. `Update` продолжает тикать на частоте vsync.

## 4. Стратегия тестирования (Пирамида)

* **Уровень 1 (Unit):** Тестирование `Scrollback` и `Grid` в оперативной памяти (Table-driven tests).
* **Уровень 2 (Integration/ANSI):** Подача эталонных байтовых потоков в VTE-парсер через `bytes.Buffer` с проверкой итоговой матрицы символов.
* **Уровень 3 (Headless GPU):** Тестирование `LayoutManager` через `ebiten.NewImage()` без создания реального окна графической подсистемы Linux. Идеально для CI/CD-пайплайнов.
* **Уровень 4 (Thread Safety):** Обязательный запуск всех тестов с флагом `go test -race` для проверки синхронизации между PTY-горутиной и Ebitengine.

## 5. План разработки (Roadmap)

### Этап 0: Архитектурные спайки (Исследования)
* Написать микро-бенчмарк для проверки кратности ширины текста с лигатурами в `text/v2` размеру ячейки `Grid`.
* Проверить выбранный ANSI-парсер через `pprof` на количество аллокаций (B/op, allocs/op) при нагрузке в 10 МБ текста.
* Изучить спецификацию Mouse Reporting (SGR mouse mode) для трансляции кликов внутрь PTY-утилит.

### Этап 1: MVP (Базовый терминал)
* Интеграция `creack/pty` и вывод монохромного текста поклеточно в Ebitengine.
* Ввод с клавиатуры.

### Этап 2: Цвет, история и лигатуры
* Внедрение ANSI-парсера.
* Разработка `Scrollback` буфера.
* Переход на Runs-рендеринг для поддержки 256/TrueColor цветов и правильной обработки лигатур кода.

### Этап 3: Оконный менеджер
* Реализация `LayoutManager` (вертикальные и горизонтальные сплиты).
* Динамический ресайз PTY.
* Маршрутизация фокуса ввода по клику.

### Этап 4: Экосистема
* Добавление вкладок (Tabs) поверх сплитов.
* **Таббар** (реализовано): верхняя полоса, вкладки равной ширины (1 вкладка — по центру, N — N равных сегментов), лейбл = номер + OSC-заголовок. Фон бара совпадает с фоном терминала (неактивные вкладки сливаются), а активная вкладка рисуется залитой «таблеткой» (rounded pill), тонированной в сторону foreground (`tabActiveTint`) — темнее фона, читается как выделенный чип. Скруглённые углы рисуются прямоугольниками + антиалиасные круги (`drawRoundedRect`), т.к. в Ebiten нет готового rounded-rect. Рендер — `internal/render/tabbar.go`; тайлинг сегментов покрыт тестами.
* Интеграция протоколов Kitty (Графика и расширенная клавиатура).
* **Файл конфигурации** (см. раздел 6): вынести захардкоженные значения (тема, шрифт, размер, scrollback) в пользовательский конфиг.

## 6. Конфигурация (Config File) — РЕАЛИЗОВАНО

Настройки читаются из файла конфигурации пакетом `internal/config` (TDD, headless). Пример — `config.example.toml`. Пока файла нет — используются значения по умолчанию (текущая светлая тема).

* **Расположение:** `$XDG_CONFIG_HOME/go-vte/config.toml` (fallback `~/.config/go-vte/config.toml`). Отсутствие файла — не ошибка: применяются значения по умолчанию.
* **Формат:** TOML (человекочитаемый, без кодогенерации). Парсинг — минимальная зависимость или ручной ридер; при ошибке парсинга — лог + дефолты, приложение не падает.
* **Настраиваемые параметры (первый срез):**
  * **Шрифт:** размер в px (`font_size`, сейчас `16`). Сам шрифт встроен в бинарник (JetBrains Mono Nerd Font) и не настраивается через конфиг.
  * **Тема:** `foreground`, `background`, `cursor`, `selection_foreground`, `selection_background`, и палитра `color0..color15` (hex `#rrggbb`). Значения по умолчанию — текущая светлая тема из `palette.go`/`draw.go`.
  * **Курсор:** стиль (`block`/`beam`/`underline`) и прозрачность.
  * **Окно:** `window_decorated` (bool, по умолчанию `true`) — рамка/заголовок окна ОС; `false` = без рамки (borderless, без тайтлбара).
  * **Scrollback:** число строк истории на панель (`scrollback_lines`, сейчас `10000`).
  * **Рендер иконок:** `icon_fill_ratio` (сейчас `0.85`).
  * **Отступы (padding):** `padding_left`, `padding_right`, `padding_top`, `padding_bottom` — инсет содержимого от краёв окна в логических px (масштабируются по device scale, как размер шрифта; по умолчанию `0`). Область отступа заливается цветом фона, сетка ячеек уменьшается под контентную область.
  * **Хоткеи вкладок:** `key_new_tab`, `key_close_tab`, `key_next_tab`, `key_prev_tab` — аккорд вида `модификаторы+клавиша` (например `ctrl+tab`). Модификаторы: `ctrl`/`control`, `shift`, `alt`/`option`; клавиша — один символ (буква/цифра/скобка) или `tab`. Дефолты: new=`ctrl+shift+t`, close=`ctrl+shift+w`, next=`ctrl+tab`, prev=`ctrl+shift+tab`. Парсятся в `config.Binding` (пакет `config`), сопоставление — `app.matches` в `HandleKey`. Входной слой (`app/input.go`, `keyName`) нормализует Ebiten-клавиши в те же токены.
* **Слои владения:** конфиг загружается один раз в `AppState` (Этап 4) и передаётся вниз (Renderer, Pane); горячая перезагрузка — опционально позже.
* **Тестирование (TDD):** отдельный пакет `internal/config` с table-driven тестами — парсинг hex-цветов, дефолты при отсутствии/битом файле, границы значений. Полностью headless, без GPU.

## 7. Поддержка VTE/ANSI (реализовано в `internal/vte`)

Парсер — конечный автомат (`parser.go`), состояние переживает границы `Write` (escape-последовательности могут приходить кусками из PTY). Всё покрыто table-driven тестами (feed байт → проверка `Grid`), плюс golden-снапшот и zero-alloc бенч. Поведение верифицируется headless, без GPU.

* **Текст и C0:** печатаемые UTF-8 руны с переносом строки, `LF`/`CR`/`TAB`/`BS`, скролл при переполнении. **Автоперенос — отложенный (VT100 `do_wrap`):** запись в последнюю колонку не двигает строку сразу, а взводит флаг `wrapPending`; фактический перенос происходит на следующей печатной руне. Это критично для TUI (neovim), которые заполняют правый край, — без этого преждевременный перенос/скролл дублировал строки. Флаг сбрасывается любым перемещением курсора / `CR`/`LF`/`TAB`/`BS`. `DECAWM` (`?7`) поддержан: при выключенном автопереносе символы у правого края перезаписывают последнюю колонку (без переноса). Покрыто `autowrap_test.go`.
* **Reflow при ресайзе (`reflow.go`):** мягкие переносы фиксируются в `Grid.wrapped[y]` (строка `y` — продолжение `y-1`; ставится в `putCell`, сбрасывается на жёстком переводе строки/очистке/скролле, переносится вместе со строками при скролле и alt-буфере). При `Resize` строки, связанные мягким переносом, склеиваются в логические и переразбиваются под новую ширину; жёсткие переводы строки сохраняются, курсор переносится на тот же символ. Вид привязан к низу: при нехватке высоты верхние строки уезжают в scrollback (только primary). Хвостовые пустые строки — черновик, не вытесняют контент (`usedRows`). Это лечит «застрявший» перенос после расширения окна (артефакт, заметный в сплитах tmux — старый `Resize` просто клиппировал матрицу без реколонки). Покрыто `reflow_test.go`.
* **CSI — курсор:** `CUP`(`H`/`f`), `CUU/CUD/CUF/CUB`(`A`/`B`/`C`/`D`), `CHA`(`G`/`` ` ``), `VPA`(`d`).
* **CSI — очистка:** `ED`(`J`) и `EL`(`K`) с режимами 0/1/2; `ECH`(`X`).
* **SGR (`m`):** сброс, bold/italic/underline/reverse, 16 цветов (30-37/90-97, 40-47/100-107), 256-цветов (`38;5;n`/`48;5;n`), truecolor (`38;2;r;g;b`/`48;2;...`).
* **Device queries:** Primary DA (`c` → `ESC[?6c`), Secondary DA (`>c`), DSR status (`5n` → `ESC[0n`) и cursor position report (`6n` → `ESC[row;colR`). Ответы пишутся обратно в PTY (`Parser.SetReply`) — без этого шеллы вроде fish зависают.
* **Альтернативный экран:** `?1049` (сохранение курсора + очистка alt), `?47`/`?1047`; primary-буфер восстанавливается при выходе. Отдельный alt-буфер в `Grid` (Resize-aware).
* **Курсор — сохранение/видимость:** `DECSC`/`DECRC` (`ESC 7`/`8`), `SCOSC`/`SCORC` (`CSI s`/`u`), `?1048`; видимость `?25` (проброшена в `Snapshot.CursorVisible`, рендер прячет скрытый курсор).
* **Мышь (SGR/X10):** отслеживание `?1000` (клики), `?1002` (+ drag с зажатой кнопкой), `?1003` (любое движение); кодировка `?1006` (SGR, `ESC[<b;x;yM`/`m`) с фолбэком на legacy X10 (`ESC[M` + байты, координаты ≤223). Состояние в `Grid` (`mouseMode`/`mouseSGR`, сброс на `RIS`), кодирование — `Grid.EncodeMouse` (чистая функция, покрыта `mouse_test.go`). Ввод: `render.Renderer.CellAt` переводит px→ячейку (учёт padding/таббара), `app/input.go:handleMouse` шлёт события через `Pane.EncodeMouse`. Колесо = кнопки 64/65. Без включённого режима события не шлются (обычный шелл игнорирует мышь). Это даёт клики по строкам/скролл в htop, mouse в tmux/vim/less.
* **Режим клавиш курсора (DECCKM, `?1`):** ncurses-приложения (htop) через `smkx` шлют `ESC[?1h` и ждут стрелки в форме SS3 (`ESC O A`), а не CSI (`ESC [ A`). `Grid.appCursorKeys` отслеживает режим (сброс на `RIS`), `Pane.AppCursorKeys()` отдаёт его во ввод (`app/input.go`), где стрелки и Home/End кодируются CSI или SS3 в зависимости от режима. Без этого стрелки в htop игнорировались (нельзя было двигать выделение).
* **Origin mode (DECOM, `?6`):** при включении адресация строки в `CUP`(`H`/`f`) и `VPA`(`d`) отсчитывается от верха региона прокрутки, а курсор запирается в регионе (`Grid.cursorTo`); включение/`DECSTBM` гомят курсор в верх региона. По умолчанию — абсолютная адресация. Сброс на `RIS`. Покрыто `origin_test.go`. (Относительное ограничение `CUU`/`CUD` границами региона пока не реализовано — редкий кейс.)
* **Регион прокрутки:** `DECSTBM`(`r`); `lineFeed`/скролл работают только внутри региона (scrollback наполняется из top-anchored primary-региона). `RI`/`IND`/`NEL` (`ESC M`/`D`/`E`), `SU`/`SD` (`CSI S`/`T`).
* **Вставка/удаление:** `IL`/`DL` (строки, `L`/`M`), `ICH`/`DCH` (символы, `@`/`P`).
* **OSC:** `OSC 0`/`2` задают заголовок окна/вкладки (→ `Grid.Title()`/`Snapshot.Title`, показывается в таббаре), терминируются `BEL` или `ST`; прочие OSC-коды проглатываются.
* **Прочее:** объявления charset (`ESC ( B` и т.п.) проглатываются; `RIS` (`ESC c`) — полный сброс.
